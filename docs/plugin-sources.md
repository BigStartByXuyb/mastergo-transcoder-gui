# 插件来源（唯一权威）

这一份是「客户端从哪儿找 `mastergo-wpf-transcoder` 插件」的**唯一权威**。别处（README、安装文档、
界面文案、注释）只留一句并指向本文，不复述逐档细节 —— 逐档清单一变，只有这一份要改。

真值源是代码：`lib/plugin-root.js` 的 `pluginPlaces()`（顺序、id、名字、「这一档归谁管」那句话都在那儿）。
下面那张表由用例锁定（`tests/consistency.test.js`）：**表与 `pluginPlaces()` 不一致就是测试失败**。

## 查找顺序（先命中先用）

下表**逐字等于** `pluginPlaces()` 给的名字与那句说明（只有这里的反引号是排版加的，比较时忽略）：

| 第几档 | 来源 | 这一档归谁管 |
| --- | --- | --- |
| 1 | 启动参数 --plugin | 启动参数 --plugin 给的那一份：只被它自己压过（--plugin 指错客户端会直接停下）。改它要在启动时换参数。 |
| 2 | 环境变量 MASTERGO_PLUGIN_ROOT | 系统环境变量给的那一份：在系统里设（或启动前设），客户端启动时继承，新起的进程才读到。 |
| 3 | Codex 插件缓存 | 这一份归 Codex / Claude 自己管：客户端只读不改，装与更新都在它们那边做。 |
| 4 | Codex 插件市场 | 这一份归 Codex / Claude 自己管：客户端只读不改，装与更新都在它们那边做。 |
| 5 | Claude 插件缓存 | 这一份归 Codex / Claude 自己管：客户端只读不改，装与更新都在它们那边做。 |
| 6 | Claude 插件市场 | 这一份归 Codex / Claude 自己管：客户端只读不改，装与更新都在它们那边做。 |
| 7 | 客户端自带 | 客户端自带的那一份：机器上没有 Codex / Claude 时，用它「下载并安装」装一份。 |

客户端自带那一份装在 `<安装根>\plugins\mastergo-wpf-transcoder\<插件版本>\`（装了多版取最高版本）。
每一档的**位置**（代码里 `pluginPlaces()` 的 `dir`）与**地盘**（`home`，写盘防线要拦的目录）也都在那
一处定义：缓存与市场共用同一个 agent 地盘基址。

## 界面怎么显示

设置 → 更新 → **插件（流水线）** 两半：

1. **查找顺序**：七档按上面的次序排成一条，每一档标出处境（正在用 / 可用 / 没有 / 与第 N 档同一份）。
2. **来源表**：来源 / 版本 / 状态 / 路径 / 操作；同一份插件只列一行（后几档并进最先命中的那一档，
   并写明「同时来自」）。

这一页**只读与查看**，不给「换用某一档」：要换用哪一份，用前两档（`--plugin` / 环境变量）指过去，
或者在系统那边把那份装/删掉。点「客户端自带」那一行的「管理…」是它自己的面板（版本 / 路径 / 解析到
哪一份 / 更新来源 / 打开目录 / 复制路径 / 检查更新 / 下载并安装）；点别的行给只读详情。

## 改动须知

动这一件事时，只有三处要动：

1. `lib/plugin-root.js` 的 `pluginPlaces()`（顺序 / 名字 / 那句话 / 位置）；
2. 本文的表格（与上面一一对应，改完跑测试会核对）；
3. 界面若新增分支，只加它必须认的那一个 id（取值见 `ui/src/lib/plugin-sources.ts` 的 `INSTALL_SLOT_ID`）。

别的文档都不复述逐档清单 —— 它们只指向本文：`tests/consistency.test.js` 挡住三种复述写法
（一行里两个以上档位名、某个档位的列表项、档位表表头）。环境变量名只在 `lib/plugin-root.js` 定义一次；
界面与界面用例不写这个字面量，标签一律用后端给的原话。
