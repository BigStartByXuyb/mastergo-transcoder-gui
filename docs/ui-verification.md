# 界面验收记录

每完成一个任务，除单元测试外，还要在真实界面上把这次涉及的功能点一遍，结论记在这里。按时间倒序。

## 怎么点

```
npm run api                                                      # 后端在 8787
npx --yes --package @playwright/cli playwright-cli open "http://127.0.0.1:8787/#board"
npx --yes --package @playwright/cli playwright-cli snapshot       # 取 ref
npx --yes --package @playwright/cli playwright-cli click <ref>
```

两条纪律：

1. ref 只在当次 snapshot 内有效。点按钮后列表会重渲染，旧 ref 会指到别的元素 —— 改状态的操作一次 snapshot 配一次 click。
2. `goto "#另一页"` 只是 hash 变化，浏览器不会重新拉 index.html。前端重新构建后必须 `reload`，否则点到的是上一份构建。

## 2026-10-01 插件来源可见、可选、可配（v0.6.25）

### 改了什么

- **插件在设置里单开一页**（与 AI Agent 分开，插件不是它的附件）：六处查找位置逐条列出来 —— 启动参数 `--plugin` / 这里选的 /
  环境变量 `MASTERGO_PLUGIN_ROOT` / Codex 缓存与市场 / Claude 缓存与市场 / 客户端自带，
  每条都有路径、有没有、是哪一版、是不是此刻生效的那一条。同一处有多份时标「共 N 份，用最高版本」。
- **可以选用其中任意一份，立刻生效**：点「用这份」把选择记进 `local.json` 的 `pluginRoot` 并原地重新定位；
  点「用自动」清掉选择回到内置顺序；插件装在别处点「选一个目录…」直接指过去（走系统选目录框）。
  有任务在跑时后端拒绝换（跑在路上的那一次正按当前这份读步骤契约）。
- **一处都没有时不再一言不发地退掉**：以前是 `exit(2)`，界面上什么都看不到；现在照常起服务，
  把已查找的路径与各自有没有逐条列出来（设置页那块红字就是它），跑流水线时给的也是同一段话。
- **取值口径只有一处**：`lib/plugin-root.js` 的 `pluginSources()` 同时供「选择」与「列出」，
  `lib/plugin.js` 的 `createPluginRuntime()` 把「哪一份在哪、现在用哪一份」收成一个原地更新的对象 ——
  runs / pending / mapping / routes 拿的都是它，换一份不用重建任何东西。

### 为什么

同一台机器上经常同时装着 Codex 与 Claude，两边各有一份插件缓存（本机实测：Codex 缓存 1.0.369、
Claude 缓存 4 个版本最高 1.0.245、Claude 市场还有一份），以前只写一行「插件: <路径>」，
分不清用的是哪一份、也不给改的机会。用户的要求是：**这些路径都列出来、环境变量那一路也能在界面里定、
并且能自己选当前应用哪一份**，默认仍然是环境变量优先、没有才按降级链。

## 2026-09-30 换版本先确认（含「回去会缺什么」）+ 分发包补齐依赖（v0.6.23）

## 2026-09-30 下载只剩一个入口 + 历史版本也校验（v0.6.21）

### 改了什么

- 三条复核意见（v0.6.20 那两次审计给的都是这三条，说法略有不同）：
  1. **两个「下载」入口**：顶部「下载 vX」与版本表行内的「下载」对同一版做同一件事，走的还不是同一条取清单路径。
     现在只留行内那一处（有新版时它就是最上面那行），顶部改成一句提示。
  2. **「文件不全」那行点不动**：切换校验失败会被标成 `ready:false`，而行内「下载」原来只对 `!installed` 显示 ——
     整行既不能切也不能重下。现在条件放宽到「没有这一份，或这一份不完整」，按钮文案相应变成「重下」。

- 顺手把下载这条路上的重复收敛掉：`stage()` 与 `downloadManifest()` 里两处「已经在下 / 本地已有」的判据合一，
  `downloadManifest` 不再带一个恒为假的 `keepCache` 参数；设置页的下载也不再自己写一套 `setWorking/失败/toast` 样板，

## 2026-09-30 历史版本也能下回来（v0.6.20）

### 改了什么

- 更新页里「历史版本」那一行原来只有记录、没有动作：本机没下过就永远切不了。现在每行多一个「下载」，
  走 `POST /api/update/stage {version}` —— 后端按那一版的 tag 取它自己的 manifest，再走同一条
  差分下载 / 校验 / materialize 流程，落到 `versions/<版本>`，这一行随即变成「可切换」。
- 版本表最后一列的表头从「版本切换」改成「操作」（同一格现在可能放「切换」或「下载」）。
- 下载/拼装进行中禁掉其它版本按钮：同一时刻只跑一条下载。

### 为什么

用户问：更新了这么多版本，为什么大多数回退不了 —— 是包被删了还是没落盘。
查证结论是**没落盘**：远端 25 个 release 的资产都在，本机 `versions/` 只有下载过的那 9 份；

## 2026-09-30 Codex 集成（对话 / 引擎版本 / 写盘）
